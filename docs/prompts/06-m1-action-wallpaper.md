## Objective
Implement the `wallpaper` action of ModeKit against ports, extend `StandardActionFactory` so all five steps are supported, and prove with end-to-end tests (real `SessionController`, `SessionStore`, stateful fakes) that a five-step session restores the system exactly, including crash recovery. This closes M1. The session controller and file formats do not change. No real adapters and no real system access in this branch: nothing here reads or writes the user's real wallpaper store. Foundation only.

## Decisions already made (record them in the docs; do not re-decide)
1. Mechanism (ADR-027, S2). Apply: for each selected display, set the desktop image of the current Space through `WorkspaceAdapter`. Capture and restore: the bytes of the wallpaper store `Index.plist`, read and written through `FileStore`, then `killall WallpaperAgent` through `ProcessRunner` on restore. The `NSWorkspace` getters are never used (S2: they misreport color and dynamic wallpapers).
2. The knowledge of the store's internal format stays out of ModeKit. The undocumented structure of `Index.plist` must be inspected and validated against the real system, which this branch does not touch; that happens in the M2 adapter branch. ModeKit therefore compares stores only through a port:
```swift
public struct WallpaperStoreFingerprint: Codable, Hashable, Sendable { public let data: Data; public init(data: Data) }
public protocol WallpaperStoreInspector: Sendable {
    /// Equal fingerprints if and only if the wallpaper configuration of every display and Space this app can change is equal. Volatile fields (timestamps such as `LastUse`) must not influence it.
    /// - Throws: `WallpaperStoreError.unrecognizedFormat(reason:)` when the data is not a wallpaper store the inspector understands.
    func fingerprint(of store: Data) throws -> WallpaperStoreFingerprint
}
```
   `WallpaperStoreError` is typed with `CustomStringConvertible`. The action fails closed: if the inspector throws, the apply fails before anything is changed.
3. Other new ports, all `Sendable`, Foundation only, documented with `///`:
   - `WorkspaceAdapter` gains `func connectedDisplays() async -> [DisplayIdentifier]` and `func setDesktopImage(_ image: URL, on display: DisplayIdentifier) async throws` (current Space of that display only; document it; the adapter throws when the file is missing or the display is gone). Keep the existing members.
   - `SolidColorImageRenderer` with `func pngData(for color: SolidColor) async throws -> Data` (the adapter renders the PNG; ModeKit has no image framework).
   - `WallpaperLocations { storeURL: URL, generatedImagesDirectory: URL }` (a plain value; ModeKit never resolves home or bundle paths, the composition root injects them, like the profiles directory).
   - `ActionPorts`: a public struct that groups every port the actions use (`defaults`, `processRunner`, `appleScriptRunner`, `workspace`, `notifier`, `fileStore`, `clock`, `imageRenderer`, `storeInspector`). `StandardActionFactory.init` becomes `init(ports: ActionPorts, wallpaperLocations: WallpaperLocations)`; the previous multi-parameter init is replaced (the parameter count would otherwise break lint). Update every caller, the harness and the tests. This is a deliberate API change of the previous branch's init; record it.
4. Wallpaper action (`WallpaperAction`, identifier `.wallpaper`, built from `ProfileStep.wallpaper(choice, displays:)`). Restore lives in a small `WallpaperRestorer` struct that the action uses for its `restore`, so recovery can build it from an identifier alone; `makeRestorer(for: .wallpaper)` returns it. Types: snapshot `{ storeData: Data }` (base64 in the session file through `PersistenceCoding`), applied state `{ displays: [DisplayIdentifier], fingerprint: WallpaperStoreFingerprint }`.
   - `capture`: `FileStore.read(storeURL)`; nil throws `WallpaperActionError.storeUnavailable`. Read only.
   - `apply`, in this order: (1) read the store and compute its fingerprint (the inspector failing, or the store missing, throws before any change); (2) resolve the displays: `.allDisplays` is `connectedDisplays()`, `.specific(set)` is that set intersected with `connectedDisplays()`, sorted; displays that are not connected are skipped silently (record "not reported to the user yet" under "Observed but not done"); an empty result changes nothing and returns an applied state with no displays and the current fingerprint; (3) produce the image: `.image(url)` is used as is; `.solidColor(color)` is rendered with `SolidColorImageRenderer` and written through `FileStore` to `generatedImagesDirectory/solid-rrggbb.png` (lowercase two-digit hex per channel; atomic and idempotent; the file stays after restore, it is a small cache); (4) `setDesktopImage` on each selected display in order; a failure throws; (5) wait for the agent to persist: poll the store, up to 50 times at 100 ms intervals through `SessionClock.sleep`, until its fingerprint differs from the one from step 1; the fingerprint at that moment is the applied fingerprint; if it never differs, throw `WallpaperActionError.storeDidNotChange`. The 100 ms and 50 are engineering guesses, not measurements: name them as constants and mark them `UNVERIFIED` in the docs; the M2 adapter branch measures the real latency and recalibrates. Known limit to document: if the target wallpaper is already exactly the current one, the store does not change and the apply fails; this is deliberate (a silent no-op would leave the wallpaper unhidden during a screen share).
   - `restore(snapshot, expecting applied)`: read the current store (nil throws `storeUnavailable`). If its bytes equal `snapshot.storeData`, return `.restored` with no write and no process. If `applied` is non-nil and the fingerprint of the current store differs from `applied.fingerprint`, return `.skippedBecauseChangedByUser` (no write, no process). Otherwise write `snapshot.storeData` to the store URL through `FileStore`, then run `/usr/bin/killall WallpaperAgent` (timeout 10 seconds; exit 0 and exit 1 are success under the same documented ambiguity as ADR-035, any other code or a thrown `ProcessError` is a failure), return `.restored`. `applied: nil` (interrupted apply) skips the fingerprint check and restores unconditionally. An inspector failure during the conditional check is a failure of the restore (do not guess).
   - Consequences to document (ADR-027 plus this branch): the restore is whole-file, so it also drops store entries for Spaces created during the session and reverts wallpaper changes the user made on displays or Spaces this app did not touch; the conditional check covers only what this app changed; the original image file, if it was deleted during the session, is not recreated; only the current Space of each selected display is changed.
5. `StandardActionFactory` supports all five steps and identifiers after this branch; `ActionError.unsupported` remains for anything else the enums might gain. Update `StandardActionFactoryTests`.
6. ADRs: ADR-038 "Wallpaper action: store bytes through `FileStore`, fail-closed apply, polling" (decisions 1, 3, 4 and consequences). ADR-039 "Store format knowledge lives in the adapter behind `WallpaperStoreInspector`" (decision 2, and the list of obligations for the M2 adapter below). Each: context, decision, consequence, "proposed by the assistant; user to confirm".
7. M2 obligations to record in `docs/STATUS.md` and `docs/07-macos-integration.md` (they are not done here): inspect the real `Index.plist` read-only and implement `WallpaperStoreInspector` with sanitized fixtures; measure the real latency between `setDesktopImageURL` and the store change and recalibrate the polling constants; verify that an atomic replace of `Index.plist` (what `FileManagerFileStore` does) followed by `killall WallpaperAgent` restores correctly, because S2 used a plain copy; implement `SolidColorImageRenderer`; map `NSScreen` to the `CGDisplayCreateUUIDFromDisplayID` UUID; test a second display, several Spaces and a full-screen Space; verify `desktopImageURL` is not needed anywhere.
