## Decisions already made (record them in the docs; do not re-decide)
1. Layout under `App/Sources/Platform/`, one file per type, named by mechanism (docs/02): `Defaults/CFPreferencesDefaultsStore`, `Process/FoundationProcessRunner`, `AppleScript/NSAppleScriptRunner`, `Workspace/AppKitWorkspaceAdapter` (with a small display-identifier mapping type), `Notifications/DistributedNotificationCenterNotifier`, `Rendering/CoreGraphicsSolidColorImageRenderer`, `Wallpaper/PropertyListWallpaperStoreInspector`, `Logging/OSSessionLogger`, `Locations/SystemLocations`. `Platform/Hotkey` and `Platform/LoginItem` are NOT part of this branch. `Features/` never imports `Platform/`. Add a one-line check for that rule to the acceptance criteria. All adapters are `Sendable` value or final types, Swift 6 strict concurrency, zero warnings (the app target treats warnings as errors).
2. `CFPreferencesDefaultsStore`: `CFPreferences` with the current user and any host; the string domain `"NSGlobalDomain"` maps to `kCFPreferencesAnyApplication`; `CFPreferencesSynchronize` before every read and after every write or removal (S1 used it; cfprefsd caching is the reason); `CFBoolean` maps to `.bool`, an integral `CFNumber` to `.integer`, anything else throws `DefaultsError.unsupportedValueType`; the boolean test uses the CF type id, not `NSNumber` bridging. `remove` succeeds when the key is absent. Reading and writing the Finder and Dock domains from the app is `UNVERIFIED` (S1 verified only Control Center and the global domain from a throwaway app): the adapter ships as `CFPreferences`, the next branch verifies it, and if it fails the replacement is the `defaults` tool through `ProcessRunner`.
3. `FoundationProcessRunner`: `Process` with the command's absolute `executableURL` and `arguments`, no shell, standard output and error discarded, a minimal fixed environment. A nonzero exit is a `ProcessResult`. Timeout: terminate with SIGTERM, then SIGKILL after a 2 second grace, then throw `ProcessError.timedOut(duration)`; the child must not outlive the call. Cancellation of the calling task terminates the child and throws `CancellationError`. A launch failure throws `ProcessError.launchFailed(reason:)`. No `DispatchQueue.main`; use `terminationHandler` and a continuation.
4. `NSAppleScriptRunner`: runs the `AppleScript` literal. A script is never executed concurrently with another one: execution is serialized on one dedicated background thread (a blocked call, such as an unanswered Automation prompt, must never block the main thread or the app). The call's result maps errors with the existing `AppleScriptError.init(code:message:)` from `NSAppleScript`'s error info (`NSAppleScriptErrorNumber`, `NSAppleScriptErrorMessage`). The `timeout` argument is a watchdog: if the call has not returned when it expires, the runner throws `AppleScriptError.timedOut` and discards the late result (an `NSAppleScript` call cannot be cancelled; the system's own -1712 arrives at 120 s, below the 130 s the Dock action passes, so in practice the system error is what the user sees). Whether `NSAppleScript` may run off the main thread without trouble is not known: document your reading of the evidence you can find locally (header docs, the S4 throwaway code) and mark the answer `UNVERIFIED` until the next branch exercises it against System Events; if you find evidence it must run on the main thread, stop and report instead of choosing silently.
5. `AppKitWorkspaceAdapter`: AppKit calls hop to the main actor inside the async methods. `runningApplications`: `NSWorkspace.shared.runningApplications` with `activationPolicy == .regular`, skipping an application whose bundle identifier is missing or fails `BundleIdentifier` validation; `isThisApplication` compares with the running app itself; `isFrontmost` with `NSWorkspace.shared.frontmostApplication`. `hide` and `unhide` act on every running instance of the bundle identifier (`NSRunningApplication.runningApplications(withBundleIdentifier:)`): no instance, `.notRunning`; at least one request accepted, `.changed`; all rejected, `.refused`. `connectedDisplays`: each `NSScreen`'s `NSScreenNumber` to `CGDirectDisplayID` to `CGDisplayCreateUUIDFromDisplayID` to a `UUID`; the same mapping resolves a `DisplayIdentifier` back to its `NSScreen`. `setDesktopImage(_:on:)`: throws a typed `WorkspaceError` (`displayNotFound`, `imageNotFound` when the file does not exist) before calling `NSWorkspace.shared.setDesktopImageURL(_:for:options:)` with empty options (the only call S2 verified); it changes the current Space only. Its effect is never exercised by an automated test.
6. `DistributedNotificationCenterNotifier`: post the name through `DistributedNotificationCenter.default()` the way the S1 throwaway app did (read its source in `presenter-spikes`; if absent, `deliverImmediately: true`, marked `UNVERIFIED`). Tests use only a private notification name of their own.
7. `CoreGraphicsSolidColorImageRenderer`: a 64 by 64 pixel sRGB bitmap filled with the color, encoded as PNG with ImageIO (the size S2 used). Tests decode the returned bytes with ImageIO and assert the PNG signature, the size and the exact pixel value.
8. `PropertyListWallpaperStoreInspector` (ADR-039). Inspect the real `Index.plist` read-only (and any S2 copies in `presenter-spikes`) and design the fingerprint from what you see: the canonical, order-independent serialization of the parts of the store that `setDesktopImageURL` was observed to change in S2 (`Displays[<display UUID>]` for every display and the empty-string entry of `Spaces`, to be confirmed against the structure you actually see), decoding nested binary property lists recursively, with every volatile field (such as `LastUse`) excluded. Entries of individual Space UUIDs must not influence the fingerprint (a Space created during the session is not a change by the user). A store whose top-level structure is not the expected one throws `WallpaperStoreError.unrecognizedFormat(reason:)` (fail closed). Tests use sanitized fixtures built from the real structure: a script or test helper that replaces every path, UUID and user-identifying string with placeholders; a test asserts the fixtures contain no `/Users/`, no real UUID of this Mac and no user name. Cover: equal stores with different volatile fields give equal fingerprints; a changed provider or configuration changes it; a new Space entry does not; key order does not; truncated, empty and wrong-shape data fail. Record in docs/07 the structure you saw (key names and value kinds only) and what you could not see, in particular that the structure after an apply of a custom image or a solid color was observed only if a S2 copy shows it; the next branch observes it under backup and may adjust the inspector.
9. `OSSessionLogger`: `os.Logger`, subsystem = the bundle identifier from `Bundle.main` (never a literal), category `session`; levels per docs/03 (`info` for state changes, `error` for failures); identifiers and session IDs public, `reason` strings private. A pure function turns a `SessionEvent` into the log line so the text is unit-tested without reading the log.
10. `SystemLocations`: resolves with `FileManager` and an injectable base for tests: the app's support directory `~/Library/Application Support/<bundle id>/` (the directory for `profiles.json` and `session.json`), the generated images directory `.../wallpapers/`, and the system wallpaper store `~/Library/Application Support/com.apple.wallpaper/Store/Index.plist` as `WallpaperLocations`. It never creates directories itself (the stores do).
11. Composition root: `App/Sources/Application/PlatformComposition.swift` builds `ActionPorts` (with `FileManagerFileStore` and `SystemSessionClock` from ModeKit), `WallpaperLocations`, the support directory URL and the `OSSessionLogger` from the adapters above, with no side effect at construction. It is the only place that instantiates the concrete adapters. Nothing uses it in a UI yet; a test builds it and checks the wiring. Do not add a `SessionController` to it, that arrives with the menu bar shell.

Russian: "Presenter управляет автоматическим скрытием Дока через System Events, пока профиль активен."). The existing catalog tests' rules apply (both languages non-empty, translator comment). Verify on the built app: the key in the built `Info.plist`, the entitlement in the signed product (`codesign -d --entitlements`), the Russian string in the built bundle's resources; quote the commands and results. Remember the verified build fact: ad-hoc signing does not apply the hardened runtime flag; do not claim it does.
