## Objective
Build a developer tool that runs the real adapters through the real session controller on this Mac, under a backup, diff and independent-restore protocol, then execute that protocol with the user present, and turn every open `UNVERIFIED` item of the adapters into a recorded verdict with evidence. This is the first time the product changes the user's real system. It ends with: the tool and the protocol in the repository, `docs/07` and the ADRs updated with measured facts, any adapter defect found fixed with a test (or reported if large), and a PR.

## Two parts, and the rule between them
- Part A (build): the tool, the scripts, their tests and docs. Safe: nothing in Part A changes the real system. Do all of Part A first and commit it.
- Part B (verify): the staged protocol below, run on the real Mac. Part B is interactive by design: asking the user to look at the screen and report is required at every stage and is not a "blocking question" under docs/10. Part B starts only after the user answers one question (AskUserQuestion) confirming they are at the Mac, have saved open work, and agree to the visible effects listed in the protocol (desktop icons and Dock flicker, the menu bar hides, the wallpaper changes briefly, TextEdit and Calculator are hidden). If the user is absent or says no, stop after Part A, open the PR with Part B marked "not run", and say so in the report. Never run Part B unattended.

## Decisions already made (record them in the docs; do not re-decide)
1. The tool is a DEBUG-only mode of the app itself, not a separate bundle: `App/Sources/DeveloperTools/AdapterCheck/`, every file wrapped in `#if DEBUG`, started with `--adapter-check <command> ...`. Reason: the Automation permission and its prompt belong to the bundle identity and its `NSAppleEventsUsageDescription`; testing the real app's bundle is the only way to see the real prompt in both languages. Release builds must contain no reference to the tool (check: build Release and `strings`/`nm` the product for the tool's type names; quote the result). In check mode the app creates no menu bar item, no window, and exits when the command finishes. Normal launches (no flag) behave exactly as before. Record as ADR-042.
2. Launch contract: `Scripts/adapter-check.sh <command> [options]` builds the Debug app (reuse `.build/DerivedData`), then runs `open -n -W -a <built app> --stdout <file> --stderr <file> --args --adapter-check <command> --result <file> ...` (launch through `open` so macOS attributes the process to the app bundle, as S4's bundles were; read how S4 launched its bundle and follow it, and say in the docs what you found). Because `open -W` does not return the program's exit code, every command writes a JSON result file (`{"status":"ok"|"failed", ...}`) and the script prints it and exits nonzero on `failed`. Events go to stdout as JSON lines (a `SessionLogger` that prints `SessionEvent`; local output, never committed).
3. Commands (exactly these):
   - `world`: read-only JSON snapshot: schema version, macOS version, the five keys the actions use (`com.apple.finder CreateDesktop`, `com.apple.dock autohide`, `com.apple.controlcenter AutoHideMenuBarOption`, `NSGlobalDomain _HIHideMenuBar`, `NSGlobalDomain AppleMenuBarVisibleInFullscreen`) read through the `CFPreferencesDefaultsStore` (type and value, or `absent`), the wallpaper store (size, SHA-256, the inspector's fingerprint or its error), the regular applications with their hidden flags, the displays (count and UUIDs). Contains local data: it is written only under the check directory.
   - `store-structure`: read-only; prints the structure of the real wallpaper store as key names and value kinds only (never values, paths or UUIDs).
   - `run --profile <name> [--hold-seconds N]`: loads profiles from the check directory's `profiles.json` with the real `ProfileStore`, builds the real controller (`StandardActionFactory` over `PlatformComposition`'s ports, `SessionStore` over the check directory, `OSSessionLogger` plus the printing logger), calls `recoverIfNeeded`, `activate`, waits `N` seconds, `deactivate`, prints the report. Also `--hide-only <bundle ids>`: builds a profile with a single `hideApps` step whose exclusions are every running regular application except the listed ones (so only the listed applications can be hidden).
   - `activate --profile <name>`: as `run` but exits right after a successful activation without deactivating (simulates a crash with an active session). `recover`: a new process that only calls `recoverIfNeeded` and prints the outcome.
   - `wallpaper-latency [--runs N]`: for each run, read the store fingerprint, call `setDesktopImage` through the adapter with a generated solid color, poll the store file every 10 ms recording the time until the inspector's fingerprint changes (cap 10 s), then restore through `WallpaperRestorer`; prints each latency and the median and 95th percentile.
   - `wallpaper-interrupt`: sets a wallpaper through the adapter and immediately (before the store changes) runs the restorer with `applied: nil`, then reports the final store fingerprint against the baseline and waits 10 s to see whether a late persist overwrote it.
   - `notify-menubar`: posts the menu bar notification through the real notifier (used by the emergency restore).
   Mutating commands (`run`, `activate`, `recover`, `wallpaper-latency`, `wallpaper-interrupt`, `notify-menubar`) require `--backup <dir>` pointing at a directory with a valid `MANIFEST.json` created by the backup script less than 24 hours ago; otherwise they refuse and change nothing.
4. Support directory: the tool never touches the real app's support directory. It uses `$HOME/presenter-check/` (profiles, `session.json`, generated wallpapers, results). A `session.json` left there by an aborted run is restored by the next `recover`.
5. Scripts under `Scripts/` (shell, `set -euo pipefail`, no dependency beyond what macOS ships and the tools in docs/11): 
   - `adapter-check-backup.sh`: creates `$HOME/presenter-check/backup-<UTC timestamp>/` with `MANIFEST.json`, `defaults export` of `com.apple.finder`, `com.apple.dock`, `com.apple.controlcenter`, `NSGlobalDomain`, `keys.tsv` (one line per action key: domain, key, type, value or `absent`, read with `defaults read-type`/`read`), a copy of the wallpaper store (the whole `com.apple.wallpaper` directory listing plus `Index.plist`), `world.json` (from the tool), the running regular applications with hidden state, `sw_vers` and the display summary, and a desktop screenshot only if `screencapture` works without any new permission (never request or grant a privacy permission to anything; if blocked, skip and say so). Prints the backup path.
   - `adapter-check-diff.sh <backup>`: compares the current system with the backup: per-key comparison against `keys.tsv` (exact), applications and hidden flags and displays against `world.json` (exact), and the wallpaper store with an independent comparison: `Scripts/compare-wallpaper-store.swift`, a standalone script (no ModeKit, no inspector code) that decodes both stores with `PropertyListSerialization`, decodes nested property lists recursively and ignores `LastUse`. Exit 0 only if everything is equal. Prints exactly what differs.
   - `adapter-check-restore.sh <backup>`: the emergency restore, independent of the code under test: for each line of `keys.tsv` write the value with `defaults write` (`-g` for `NSGlobalDomain`) or `defaults delete` when it was absent; copy `Index.plist` back and `killall WallpaperAgent`; run `adapter-check.sh notify-menubar`; print what it did and what it could not do (for example a Dock that is still auto-hidden after the key was fixed: say so). Use it only when `recover` cannot.
   Make them executable, lint-clean in spirit (quoting, no unchecked globbing), and document them.
6. Part A tests (`App/Tests/DeveloperTools/`): argument parsing, the backup-manifest gate (missing, malformed, stale, valid), profile building for `--hide-only` (exclusions are all running apps except the listed, with an injected application list), `world` serialization with injected readers (no real system), the percentile function, the result-file writer, the printing logger. None of these touches the real system. The scripts are exercised only in Part B.
7. The calibration rule for the wallpaper polling (ADR-038): keep the 100 ms interval; set the poll count to `max(50, ceil(4 x p95 latency / 100 ms))`, where p95 is measured over at least 10 runs on this Mac. If the rule changes the constant, change it in ModeKit (`WallpaperAction`) with its tests in this branch. Record the measured latencies.
8. If a verification shows an adapter or action defect, fix it in this branch as its own commit with a regression test, when the fix is small (about 120 lines or less, no change to an ADR-confirmed behavior). Otherwise stop the stage, restore, and report the defect and the minimal fix. If `CFPreferences` cannot read or write the Finder or Dock domain from the app, that is such a case: report it and propose the `defaults`-tool store through `ProcessRunner`; implement it only if it is small.
9. Results are recorded in `docs/07-macos-integration.md` as new spike-log style entries (`### C<N> <date> macOS <version>`, each line labelled **machine** or **human**, as the existing entries), and in the affected ADRs as a dated "Verified on this Mac" or "Corrected" note appended to the existing text (never rewrite history). Nothing personal is committed: record counts, shapes and timings, not bundle identifiers of the user's apps, paths, real UUIDs or store contents.

## Protocol for Part B (staged; no stage is skipped; order is by risk)
Every mutating stage follows the M0 cycle: baseline (`world`), announce the visible effect to the user in one line, run, ask the user what they saw, the restore (the session's own deactivate), then `adapter-check-diff.sh`. If a diff is not empty, or a command crashes with a session active, or anything unexpected appears: run `recover`, then the diff again, then if needed `adapter-check-restore.sh`, report exactly what differs and stop; do not continue to the next stage.
- B0 Preconditions: run the backup script, print the path, capture `world`, ask the user (once) for the preconditions of the later stages: at least two Spaces on the current display, TextEdit and Calculator may be opened and hidden, whether a second display is attached, whether they can open one app full screen when asked.
- B1 Read parity (no change): `world` against `defaults read` and `defaults read-type` for the five keys (shell, independent of the app); the store hash against `shasum`. Verifies `CFPreferences` reads of the Finder and Dock domains and the menu bar keys from the real app.
- B2 `killall` exit codes (no change to the user's settings): `killall` of a process name that does not exist, exit code. Record. (The exit code for a found-but-unsignalled process cannot be tested: say so.)
- B3 Desktop icons: profile with the desktop icons step, hold 8 s. Verifies the `CFPreferences` write to `com.apple.finder`, the Finder restart through `FoundationProcessRunner`, the icons hidden and back (human), exit code 0 of `killall Finder`, diff empty.
- B4 Dock: profile with the Dock step. First `tccutil reset AppleEvents <the app's bundle identifier>` (only that identifier, never another). Run: the real Automation prompt appears; ask the user to type the prompt text exactly and say which language it is in; the user chooses Allow; the Dock changes (human); hold 8 s; restore; diff. Then the denial path: reset again, the user chooses Don't Allow: expect `AppleScriptError.notAuthorized` mapped, the activation fails and rolls back, nothing changed, state idle. Then the Russian prompt: reset, launch with `-AppleLanguages "(ru)"` through the script's options, the user reports the text. Then the timeout: reset, leave the prompt unanswered, expect the system's -1712 at about 120 s mapped to `timedOut`, measure the time (machine), the user dismisses nothing; confirm nothing changed. Finally leave the permission granted (Allow) for the following stages. Verifies `NSAppleScript` off the main thread against System Events, the prompt text in both languages, -1743, -1712, the 130 s watchdog is not the one that fires.
- B5 Menu bar: profile with the menu bar step, hold 8 s, on the desktop; ask the user to open one app full screen first and repeat (hold 8 s). Verifies reading and writing the three keys from the real app and the notification posted from the real app (human: the menu bar hid and came back, in both desktop and full-screen), diff empty.
- B6 Hide apps (only the applications you open): `open -a TextEdit` and `open -a Calculator`; `run --hide-only <TextEdit's id>,<Calculator's id>` hold 8 s; ask what the user saw; then: `open -n -a TextEdit` for a second instance and repeat (several instances: both instances hidden? read each `isHidden` through a small read-only probe or `world`); the user manually unhides one app during the hold (the outcome must be `restored` for the others and the unhidden one left alone) and a second run where the user unhides all (outcome `skippedBecauseChangedByUser`); a run where the user quits Calculator during the hold (it must not be relaunched); the full-screen variant (the user puts TextEdit in full screen: what does `hide()` return and what happens). Record `hide()` and `unhide()` return values (machine, from the events) and effects (human). Close the test apps at the end.
- B7 Wallpaper: first `store-structure` (shapes only). Then `run` with a solid color profile on the current Space, hold 10 s: human confirms the color on this Space and that the other Space is unchanged (the user visits it); store structure again (shapes only) to see what the apply changed; the restore; diff (independent store comparison must be equal ignoring `LastUse`). Verifies `setDesktopImage`, the inspector against a real post-apply store, the polling in a real run, the atomic replace of `Index.plist` followed by `killall WallpaperAgent` (the user confirms the original wallpaper is back, including a dynamic or image original if that is what they have). Then `wallpaper-latency --runs 12`, apply the calibration rule. Then an image profile (a PNG you generate in the check directory). Then `wallpaper-interrupt`: record whether the final store equals the baseline and whether a late persist changed it after 10 s, and what the user sees. If the user has a second display: all displays and a specific display; otherwise record "untested".
- B8 Whole session: the all-five profile, hold 15 s, restore, diff; then the crash path: `activate` the same profile, kill the app process with `kill -9`, `recover` in a new process, diff. Reboot recovery is NOT tested here (it belongs to the later M2 acceptance).
- B9 User changes during a session: `run` the all-five profile with a long hold (60 s); the user changes the Dock auto-hide setting in System Settings and, separately, changes the wallpaper through System Settings; the deactivate must report `dock` and `wallpaper` as skipped and leave the user's values (this validates the wallpaper fingerprint detecting a real user change: the most important result of the whole protocol). Then the user sets both back by hand, or you run the restore script, and the final diff must be empty.
- B10 Final: `adapter-check-diff.sh` against the original backup must be empty. Quote it. List anything left changed and how to undo it.

## Requirements
- Architecture: the tool is `#if DEBUG` only and absent from Release (verified); `Features/` never imports `Platform/` or `DeveloperTools/`; ModeKit imports Foundation only except the calibration change which touches constants only.
- Code: follow docs/03-code-standards.md. No TODOs, no stubs, no commented-out code, no unrequested abstractions, no `Utils`/`Helpers`/`Manager`/`Common` names, no boolean parameters, no force unwraps, no `try?` that discards a failure without a justifying comment, no `print` outside the tool's explicit output type (the tool's stdout writer is the one allowed exception, in one type). Files at most 300 lines, functions at most 50.
- Safety: the mutating commands refuse without a valid, fresh backup; a session left active by an aborted run is restored by `recover`; the emergency restore script does not depend on the app.
- Each Part B stage prints before it runs: what will visibly happen, for how long, and how it is restored.
